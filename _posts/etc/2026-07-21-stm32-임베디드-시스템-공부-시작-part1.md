<p>바야흐로 방학이 시작된 지 일주일.</p>
<p>지난주는 정보처리기사 실기시험을 준비하느라 꽤 험난한 시간을 보냈다. 시험이 끝나고 잠깐 쉬고 싶은 마음도 있었지만, 이번 방학을 그대로 흘려보내기는 아쉬웠다! 시간은 빠르게 흘러갈 것임에!! 
부지런히 움직여 보자!</p>
<p>그래서 이번 주부터 4주 동안 임베디드 시스템 강의를 완강하는 프로젝트에 돌입했다.</p>
<p>단순히 코드를 작성하는 것에서 끝나는 것이 아니라, 센서와 직접 통신하고 전력을 제어하며 내가 작성한 코드로 실제 하드웨어를 움직여 보고 싶었다.</p>
<p>그동안 웹이나 AI처럼 운영체제 위에서 실행되는 프로그램을 주로 다뤘다면, 이번에는 운영체제가 없는 MCU 환경에서 프로그램이 어떻게 실행되고 하드웨어를 어떻게 제어하는지 직접 경험해 보려고 한다.</p>
<hr />
<h2 id="1-강의시작전-필수-준비">1. 강의시작전 필수 준비</h2>
<p>강의를 따라가기 위해서는 기본적인 C언어 문법을 이해하고 있어야 한다.</p>
<p>단순히 변수와 반복문을 사용하는 수준을 넘어 다음 내용을 어느 정도 다룰 수 있어야 한다.</p>
<ul>
<li>배열</li>
<li>함수</li>
<li>포인터</li>
<li>구조체</li>
<li>동적 메모리 할당</li>
<li>연결 리스트</li>
</ul>
<p>연결 리스트를 직접 구현할 수 있는 정도의 C언어 실력이 권장.</p>
<p>실습을 진행하려면 STM32 개발 보드가 필요하다. 다만 강의 초반에는  컴퓨터 구조, MCU, ARM, 임베디드 시스템의 전체 흐름을 배우는 이론 수업이 중심이기 때문에 처음부터 개발 보드가 필요한 것은 아니지만, 초반에 개발보드를 디버깅장치에 연결하는 것부터 먼저 시작을 해뒀다.</p>
<p>이번 강의에서 사용하는 개발 환경은 다음과 같다.</p>
<ul>
<li>개발 도구: STM32CubeIDE</li>
<li>개발 보드: STM32F103C8T6</li>
<li>프로그램 다운로드 및 디버깅 장치: ST-LINK</li>
<li>개발 언어: C언어</li>
<li>프로그램 저장 위치: MCU 내부 Flash Memory</li>
</ul>
<hr />
<h2 id="2-4주동안-배우게될-내용">2. 4주동안 배우게될 내용</h2>
<p>먼저 임베디드 시스템이 전체 컴퓨터 구조에서 어떤 위치에 있는지 배우고, 실제 임베디드 제품이 만들어지는 과정부터 살펴본다.</p>
<ul>
<li>임베디드 시스템의 개념</li>
<li>CPU, GPU, Memory의 역할</li>
<li>MCU와 MPU의 차이</li>
<li>AVR과 ARM의 차이</li>
<li>ARM이 임베디드 시장에서 널리 사용되는 이유</li>
<li>STM32 제품명 읽는 방법</li>
<li>MCU 선정 시 고려할 사항</li>
<li>실제 임베디드 제품이 만들어지는 과정</li>
<li>회로도, PCB, Gerber File의 개념</li>
<li>Firmware와 BSP의 개념</li>
</ul>
<p>이론 학습 이후에는 STM32 개발 보드를 이용해 다음 내용을 순차적으로 실습할 예정!</p>
<ol>
<li>GPIO</li>
<li>Input과 Output</li>
<li>Interrupt</li>
<li>I²C</li>
<li>SPI</li>
<li>DMA</li>
<li>내부 Flash Memory</li>
<li>Timer</li>
<li>센서 통신</li>
<li>간단한 제품 제어</li>
</ol>
<p>처음에는 STM32에서 제공하는 HAL Driver를 이용해 주변장치를 제어하고, 이후에는 HAL을 사용하지 않고 레지스터나 GPIO를 직접 제어하는 과정도 진행한다.</p>
<p>단순히 함수 사용법만 배우는 것이 아니라 그 함수가 내부적으로 하드웨어를 어떻게 제어하는지 이해하는 것이 목표다.</p>
<hr />
<h2 id="3-큰-그림을-먼저-그려야-하는-이유">3. 큰 그림을 먼저 그려야 하는 이유</h2>
<p>개발자는 모든 기술을 완벽하게 공부한 뒤 개발을 시작할 수 없다.</p>
<p>새로운 기술을 배울 때 각각의 명령어나 사용법만 외우면 환경이 조금만 달라져도 다시 처음부터 헤매게 된다.</p>
<p>반면 기술들이 서로 어떤 관계를 가지고 있는지 큰 구조를 이해하면, 처음 접하는 도구라도 비교적 빠르게 적응할 수 있다.</p>
<p>예를 들어 다음 도구들은 서로 다른 개발 환경에서 사용된다.</p>
<ul>
<li>NPM</li>
<li>PIP</li>
<li>apt-get</li>
<li>각종 마켓플레이스</li>
</ul>
<p>이름과 사용 방법은 다르지만 저장소에서 필요한 프로그램이나 패키지를 내려받는다는 공통점이 있다.</p>
<p>이처럼 개별 명령어를 암기하기 전에 저장소, 패키지, 의존성이라는 공통 개념을 이해하면 문제가 발생했을 때 원인을 찾기 쉬워진다.</p>
<h3 id="visual-studio와-visual-studio-code의-차이">Visual Studio와 Visual Studio Code의 차이</h3>
<p>Visual Studio와 Visual Studio Code도 같은 관점에서 이해할 수 있다.</p>
<p>Visual Studio는 컴파일러와 디버거를 비롯해 개발에 필요한 여러 기능이 포함된 통합 개발 환경이다.</p>
<p>반면 Visual Studio Code는 기본적으로 코드 편집기에 가깝다. 따라서 사용하는 언어에 맞는 컴파일러와 확장 프로그램을 별도로 설치하고 설정해야 한다.</p>
<p>결국 중요한 것은 특정 프로그램의 버튼 위치를 외우는 것이 아니라 다음 요소들이 각각 어떤 역할을 하는지 이해하는 것이다.</p>
<ul>
<li>코드 편집기</li>
<li>컴파일러</li>
<li>링커</li>
<li>빌드 도구</li>
<li>디버거</li>
<li>실행 환경</li>
</ul>
<p>STM32CubeIDE의 사용법만 외우는 것이 아니라, 내가 작성한 C언어 코드가 어떤 과정을 거쳐 MCU의 Flash Memory에 저장되고 실행되는지 이해해야 한다.</p>
<hr />
<h2 id="4-전기전자와-컴퓨터의-시작점">4. 전기전자와 컴퓨터의 시작점</h2>
<p>컴퓨터와 임베디드 시스템을 깊게 내려가 보면 결국 전기의 흐름에서 시작한다.</p>
<p>전류가 흐르는 상태와 흐르지 않는 상태를 이용해 1과 0을 표현하고, 이 두 가지 값을 조합해 데이터를 처리한다.</p>
<h3 id="41-트랜지스터">4.1 트랜지스터</h3>
<p>트랜지스터는 컴퓨터와 디지털 회로를 구성하는 핵심 부품이다.</p>
<p>트랜지스터는 대표적으로 다음 두 가지 역할을 한다.</p>
<ul>
<li>전류를 흐르게 하거나 차단하는 스위치</li>
<li>입력된 신호를 크게 만드는 증폭기</li>
</ul>
<p>디지털 회로에서는 주로 스위치 기능을 이용해 0과 1을 표현한다.</p>
<p>여러 개의 트랜지스터를 조합하면 다음과 같은 논리 게이트를 만들 수 있다.</p>
<ul>
<li>AND</li>
<li>OR</li>
<li>NOT</li>
<li>XOR</li>
</ul>
<p>이러한 논리 게이트를 수없이 조합하여 CPU와 Memory를 만든다.</p>
<p>결국 우리가 작성한 프로그램도 가장 아래 단계에서는 수많은 트랜지스터의 전기적 상태 변화로 실행되는 셈이다.</p>
<h3 id="42-2진수와-불-대수">4.2 2진수와 불 대수</h3>
<p>컴퓨터는 기본적으로 0과 1을 이용해 데이터를 처리한다.</p>
<p>불 대수는 참과 거짓을 기반으로 논리 연산을 수행하는 체계다.</p>
<p>프로그래밍에서는 여러 조건을 판단할 때 사용된다.</p>
<pre><code class="language-c">if (is_running &amp;&amp; is_connected) {
    // 두 조건이 모두 참일 때 실행
}</code></pre>
<p>참과 거짓만 필요한 값에는 Boolean 자료형을 사용하면 코드의 의미를 명확하게 표현할 수 있다.</p>
<p>다만 Boolean 자료형이 실제 메모리에서 반드시 1비트만 차지하는 것은 아니다. 실제 크기는 언어, 컴파일러, 시스템 구조에 따라 달라질 수 있다.</p>
<hr />
<h2 id="5-컴퓨터의-주요-구성-요소">5. 컴퓨터의 주요 구성 요소</h2>
<h3 id="51-cpu">5.1 CPU</h3>
<p>CPU는 프로그램의 명령어를 해석하고 연산을 수행하는 장치다.</p>
<p>CPU 내부에는 연산 장치와 여러 종류의 레지스터가 존재한다.</p>
<p>레지스터는 CPU가 현재 처리하고 있는 데이터나 주소를 임시로 저장하는 매우 빠른 기억 장치다.</p>
<p>CPU는 일반적으로 다음 과정을 반복한다.</p>
<ol>
<li>메모리에서 명령어를 가져온다.</li>
<li>명령어를 해석한다.</li>
<li>필요한 데이터를 가져온다.</li>
<li>연산을 수행한다.</li>
<li>결과를 저장한다.</li>
</ol>
<p>이러한 과정을 명령어의 Fetch, Decode, Execute 과정이라고 볼 수 있다.</p>
<h3 id="52-gpu">5.2 GPU</h3>
<p>GPU는 원래 그래픽 연산을 빠르게 처리하기 위해 개발된 장치다.</p>
<p>그래픽 작업은 비슷한 계산을 많은 데이터에 반복하는 경우가 많기 때문에 GPU는 병렬 처리에 적합한 구조를 가진다.</p>
<p>현재는 그래픽뿐 아니라 다음과 같은 분야에서도 사용된다.</p>
<ul>
<li>딥러닝 학습</li>
<li>인공지능 추론</li>
<li>영상 처리</li>
<li>과학 계산</li>
<li>대규모 병렬 연산</li>
</ul>
<h3 id="53-주기억장치">5.3 주기억장치</h3>
<p>주기억장치는 CPU가 현재 사용하고 있는 프로그램과 데이터를 저장하는 공간이다.</p>
<h4 id="ram">RAM</h4>
<p>RAM은 실행 중인 프로그램과 데이터를 임시로 저장한다.</p>
<p>저장장치에 있는 프로그램을 RAM으로 불러오면 CPU가 해당 데이터에 빠르게 접근할 수 있다.</p>
<p>RAM은 전원이 꺼지면 데이터가 사라지는 휘발성 메모리다.</p>
<p>RAM의 용량이 크면 여러 프로그램을 동시에 실행하거나 큰 데이터를 처리하는 데 유리하다.</p>
<h4 id="rom">ROM</h4>
<p>ROM은 전원이 꺼져도 데이터가 유지되는 비휘발성 메모리다.</p>
<p>초기의 ROM은 저장된 내용을 읽는 용도로 사용되었지만, 현재는 Flash Memory처럼 전기적으로 내용을 수정할 수 있는 비휘발성 메모리도 널리 사용된다.</p>
<h3 id="54-보조기억장치">5.4 보조기억장치</h3>
<p>보조기억장치는 운영체제, 프로그램, 문서, 사진 등을 장기간 보관하는 장치다.</p>
<p>대표적으로 HDD와 SSD가 있다.</p>
<h4 id="hdd">HDD</h4>
<p>HDD는 회전하는 디스크와 헤드를 이용해 데이터를 읽고 쓴다.</p>
<p>기계적으로 움직이는 부품이 있기 때문에 충격에 약하지만, 대용량 저장 비용이 비교적 저렴하다.</p>
<h4 id="ssd">SSD</h4>
<p>SSD는 Flash Memory를 이용해 데이터를 저장한다.</p>
<p>기계적으로 움직이는 부분이 없기 때문에 HDD보다 속도가 빠르고 충격에 강하다.</p>
<hr />
<h2 id="6-임베디드-시스템">6. 임베디드 시스템</h2>
<p>임베디드 시스템은 특정 기능을 수행하기 위해 제품 내부에 포함되는 컴퓨터 시스템이다.</p>
<p>일반적인 PC가 다양한 프로그램을 실행할 수 있는 범용 컴퓨터라면, 임베디드 시스템은 정해진 목적을 수행하는 데 집중한다.</p>
<p>대표적인 예는 다음과 같다.</p>
<ul>
<li>온도 측정 장치</li>
<li>전자 체중계</li>
<li>교통카드 단말기</li>
<li>가전제품</li>
<li>자동차 제어 장치</li>
<li>공장 자동화 장비</li>
<li>IoT 기기</li>
<li>항공기 제어 시스템</li>
</ul>
<p>임베디드 시스템은 하드웨어와 소프트웨어가 결합되어 동작한다.</p>
<p>모든 기능을 하드웨어만으로 구현하면 수정하거나 업그레이드하기 어렵기 때문에 많은 기능을 소프트웨어로 구현한다.</p>
<p>제품 안에서 특정 기능을 수행하는 소프트웨어를 임베디드 소프트웨어 또는 Firmware라고 부를 수 있다.</p>
<hr />
<h2 id="7-임베디드-개발자와-일반-소프트웨어-개발자의-차이">7. 임베디드 개발자와 일반 소프트웨어 개발자의 차이</h2>
<p>웹이나 AI 개발자는 대부분 운영체제가 설치된 컴퓨터에서 실행되는 프로그램을 만든다.</p>
<p>임베디드 개발자는 특정 하드웨어에서 동작하는 프로그램을 만든다.</p>
<p>임베디드 프로그램의 기본적인 개발 과정은 다음과 같다.</p>
<ol>
<li>C언어로 소스 코드 작성</li>
<li>소스 코드 컴파일</li>
<li>실행 가능한 파일 생성</li>
<li>디버거를 이용해 MCU의 Flash Memory에 기록</li>
<li>MCU에서 프로그램 실행</li>
<li>실제 하드웨어 동작 확인</li>
<li>문제가 있으면 코드와 회로를 함께 점검</li>
</ol>
<p>임베디드 환경에는 운영체제가 없는 경우도 많다.</p>
<p>이러한 환경에서는 개발자가 하드웨어 레지스터, 메모리 구조, Interrupt, Timer 등을 직접 제어해야 한다.</p>
<p>때로는 프로그램이 올바르게 작성되어 있어도 다음과 같은 이유로 정상적으로 동작하지 않을 수 있다.</p>
<ul>
<li>전원 부족</li>
<li>잘못된 배선</li>
<li>통신 Pin 연결 오류</li>
<li>Clock 설정 오류</li>
<li>센서 불량</li>
<li>드라이버 문제</li>
<li>디버거 연결 문제</li>
</ul>
<p>따라서 임베디드 개발자는 코드뿐 아니라 기본적인 하드웨어 상태도 확인할 수 있어야 한다.</p>
<hr />
<h2 id="8-mpu와-mcu">8. MPU와 MCU</h2>
<h3 id="81-mpu">8.1 MPU</h3>
<p>MPU는 연산을 담당하는 프로세서를 중심으로 구성된 장치다.</p>
<p>일반적으로 외부에 다음 장치들을 별도로 연결해야 한다.</p>
<ul>
<li>RAM</li>
<li>Flash Memory</li>
<li>저장장치</li>
<li>입출력 장치</li>
<li>주변장치</li>
</ul>
<p>PC의 CPU나 라즈베리파이에 사용되는 애플리케이션 프로세서가 대표적인 예다.</p>
<p>라즈베리파이는 프로세서, 메모리, 입출력 장치 등이 하나의 기판에 구성된 SBC다.</p>
<p>운영체제를 설치할 수 있고 일반 컴퓨터와 비슷한 방식으로 개발할 수 있기 때문에, 운영체제가 없는 MCU를 직접 제어하는 실습과는 차이가 있다.</p>
<h3 id="82-mcu">8.2 MCU</h3>
<p><img alt="" src="https://velog.velcdn.com/images/addung/post/1009e8ae-5a9d-435f-b048-0f679e754d09/image.jpg" /></p>
<p>MCU는 하나의 칩 내부에 다음 요소를 통합한 장치다.</p>
<ul>
<li>CPU Core</li>
<li>Flash Memory</li>
<li>SRAM</li>
<li>GPIO</li>
<li>Timer</li>
<li>ADC</li>
<li>UART</li>
<li>SPI</li>
<li>I²C</li>
<li>기타 주변장치</li>
</ul>
<p>Arduino와 STM32 계열 제품이 대표적인 MCU다.</p>
<p>STM32는 ARM에서 설계한 Cortex Core를 사용한다.</p>
<p>ARM이 CPU Core의 구조를 설계하면 STMicroelectronics가 해당 설계를 바탕으로 Memory, GPIO, Timer, ADC 등의 주변장치를 추가하여 하나의 MCU로 만든다.</p>
<p>ARM은 MCU 완제품을 직접 생산하는 회사라기보다 CPU 구조와 Core 설계를 개발하여 반도체 제조사에 라이선스하는 회사에 가깝다.</p>
<hr />
<h2 id="9-실제-임베디드-제품이-만들어지는-과정">9. 실제 임베디드 제품이 만들어지는 과정</h2>
<h3 id="91-기획">9.1 기획</h3>
<p>먼저 제품이 어떤 기능을 수행할 것인지 결정한다.</p>
<p>예를 들어 온도에 따라 팬을 동작시키는 장치라면 다음 요소를 정해야 한다.</p>
<ul>
<li>측정할 온도 범위</li>
<li>사용할 온도 센서</li>
<li>표시 장치</li>
<li>동작 조건</li>
<li>전원 방식</li>
<li>제품 크기</li>
<li>예상 가격</li>
</ul>
<h3 id="92-부품-조사-및-선정">9.2 부품 조사 및 선정</h3>
<p>제품의 기능과 예산에 맞는 부품을 선택한다.</p>
<p>MCU를 선정할 때는 다음 항목을 고려해야 한다.</p>
<ul>
<li>가격</li>
<li>성능</li>
<li>소비 전력</li>
<li>Flash Memory와 RAM 용량</li>
<li>GPIO 개수</li>
<li>UART, SPI, I²C 등의 통신 기능</li>
<li>ADC와 Timer 제공 여부</li>
<li>부품 공급 가능성</li>
<li>개발 자료와 예제 코드</li>
<li>개발 보드 제공 여부</li>
</ul>
<p>상용 제품을 개발할 때는 장기간 안정적으로 부품을 공급받을 수 있는지도 중요하다.</p>
<p>반면 과제나 시제품에서는 부품의 단가보다 얼마나 빠르고 쉽게 구현할 수 있는지를 우선하기도 한다.</p>
<h3 id="93-회로도-작성">9.3 회로도 작성</h3>
<p>회로도는 부품 사이의 전기적인 연결 관계를 표현한 그림이다.</p>
<p>회로도에는 MCU, 센서, 저항, 전원 부품 등이 어떤 방식으로 연결되는지가 표시된다.</p>
<p>회로도는 부품의 실제 위치를 나타내는 그림이 아니라 부품 간의 관계를 나타내는 설계도에 가깝다.</p>
<h3 id="94-pcb-artwork">9.4 PCB Artwork</h3>
<p>회로도를 바탕으로 실제 PCB 위에 부품을 배치하고 구리 배선의 경로를 설계한다.</p>
<p>이 과정을 PCB Artwork 또는 PCB Layout이라고 한다.</p>
<h3 id="95-gerber-file-생성">9.5 Gerber File 생성</h3>
<p>Gerber File은 PCB 제작 장비가 이해할 수 있는 생산용 파일이다.</p>
<p>다음과 같은 정보가 포함될 수 있다.</p>
<ul>
<li>구리 배선</li>
<li>부품 Pad</li>
<li>기판 외곽선</li>
<li>구멍 위치</li>
<li>실크 인쇄</li>
</ul>
<h3 id="96-pcb-제작-및-부품-실장">9.6 PCB 제작 및 부품 실장</h3>
<p>Gerber File을 PCB 제작 업체에 전달하면 실제 기판이 제작된다.</p>
<p>이후 필요한 부품을 구매하고 PCB 위에 부품을 부착한다.</p>
<p>부품을 PCB에 납땜하거나 장착하는 과정을 실장이라고 한다.</p>
<h3 id="97-기본-하드웨어-테스트">9.7 기본 하드웨어 테스트</h3>
<p>PCB가 완성되면 먼저 기본적인 하드웨어 상태를 확인한다.</p>
<ul>
<li>전원 전압 확인</li>
<li>단락 여부 확인</li>
<li>소비 전류 확인</li>
<li>MCU 동작 여부 확인</li>
<li>주요 신호 확인</li>
</ul>
<p>회로에 문제가 있을 경우 점퍼선을 이용해 잘못된 부분을 우회하거나 수정하기도 한다.</p>
<h3 id="98-기본-소프트웨어-테스트">9.8 기본 소프트웨어 테스트</h3>
<p>하드웨어가 정상적으로 보이면 간단한 프로그램을 실행한다.</p>
<p>예를 들어 LED를 점멸하거나 UART로 문자열을 출력하여 MCU와 디버거가 정상적으로 동작하는지 확인한다.</p>
<h3 id="99-센서와-주변장치-테스트">9.9 센서와 주변장치 테스트</h3>
<p>이후 온도 센서, 디스플레이, 모터, 통신 모듈 등을 하나씩 연결하여 정상적으로 통신하는지 확인한다.</p>
<p>이 단계에서는 소프트웨어 문제와 하드웨어 문제가 함께 발생할 수 있다.</p>
<p>따라서 코드만 확인하는 것이 아니라 배선, 전압, Clock, 통신 파형도 함께 점검해야 한다.</p>
<h3 id="910-완성-프로그램-구현">9.10 완성 프로그램 구현</h3>
<p>하드웨어와 각 부품이 정상적으로 동작하는 것이 확인되면 제품의 전체 기능을 구현한다.</p>
<p>이번 강의는 PCB 제작과 부품 실장이 완료된 STM32 개발 보드에 프로그램을 작성하는 단계부터 시작한다.</p>
<hr />
<h2 id="10-avr">10. AVR</h2>
<p>AVR은 Atmel에서 개발한 MCU 계열이다. 현재 Atmel은 Microchip에 인수되었다.</p>
<p>대표적인 제품으로 ATmega128이 있다.</p>
<p>ATmega128은 다음과 같은 특징을 가진다.</p>
<ul>
<li>8비트 MCU</li>
<li>128KB Flash Memory</li>
<li>GPIO 제공</li>
<li>UART와 SPI 통신 지원</li>
<li>내부 Flash Memory에 프로그램 저장</li>
<li>ISP 방식의 프로그램 다운로드 지원</li>
</ul>
<p>AVR은 구조가 비교적 단순하여 MCU의 기본적인 동작을 공부하는 데 적합하다.</p>
<p>ATmega128이라는 이름의 <code>128</code>은 Flash Memory 용량인 128KB를 의미한다.</p>
<p>AVR의 각 GPIO Pin은 1비트의 값을 입력하거나 출력한다.</p>
<p>CPU가 내부적으로 8비트 단위로 데이터를 처리하기 때문에 GPIO Pin을 8개씩 묶어 Port A, Port B와 같은 이름으로 관리한다.</p>
<hr />
<h2 id="11-arm">11. ARM</h2>
<p>ARM은 CPU Core의 구조를 설계하고 이를 다른 반도체 회사에 라이선스한다.</p>
<p>다음과 같은 회사들이 ARM Core를 기반으로 MCU와 프로세서를 만든다.</p>
<ul>
<li>STMicroelectronics</li>
<li>NXP</li>
<li>Texas Instruments</li>
<li>Microchip</li>
<li>Samsung</li>
<li>Qualcomm</li>
</ul>
<p>ARM 기반 제품은 다음과 같은 장점을 가진다.</p>
<ul>
<li>높은 처리 성능</li>
<li>낮은 소비 전력</li>
<li>다양한 제품군</li>
<li>풍부한 주변장치</li>
<li>여러 제조사에서 제품 생산</li>
<li>개발 자료와 예제 코드가 많음</li>
</ul>
<p>현재 임베디드 시장에서는 ARM Cortex-M 계열 MCU가 널리 사용된다.</p>
<hr />
<h2 id="12-arm-cortex-제품군">12. ARM Cortex 제품군</h2>
<p>ARM Cortex 제품군은 대표적으로 A, R, M 계열로 구분된다.</p>
<h3 id="cortex-a">Cortex-A</h3>
<p>고성능 응용 프로그램을 실행하는 프로세서에 사용된다.</p>
<ul>
<li>스마트폰</li>
<li>태블릿</li>
<li>리눅스 장치</li>
<li>고성능 임베디드 시스템</li>
</ul>
<p>운영체제를 실행하는 애플리케이션 프로세서에 주로 사용된다.</p>
<h3 id="cortex-r">Cortex-R</h3>
<p>실시간 처리와 높은 신뢰성이 필요한 시스템에 사용된다.</p>
<ul>
<li>자동차 제어</li>
<li>저장장치 제어</li>
<li>산업용 실시간 시스템</li>
</ul>
<h3 id="cortex-m">Cortex-M</h3>
<p>MCU에 사용되는 저전력 Core다.</p>
<ul>
<li>Cortex-M0, M0+: 저가형 및 저전력 제품</li>
<li>Cortex-M3: 범용 산업용 MCU</li>
<li>Cortex-M4: DSP 명령과 부동소수점 연산 지원 제품군</li>
<li>Cortex-M7: 고성능 MCU</li>
<li>Cortex-M33: 보안 기능이 강화된 MCU</li>
</ul>
<p>강의에서 사용하는 STM32F103C8T6는 Cortex-M3 Core를 사용한다.</p>
<p>Cortex 제품명 뒤의 숫자가 높다고 해서 모든 조건에서 반드시 더 좋은 제품이라는 의미는 아니다.</p>
<p>제품마다 성능, 소비 전력, 가격, 주변장치 구성이 다르기 때문에 개발 목적에 맞는 제품을 선택해야 한다.</p>
<hr />
<h2 id="13-risc와-cisc">13. RISC와 CISC</h2>
<h3 id="131-risc">13.1 RISC</h3>
<p>RISC는 비교적 단순한 명령어를 빠르게 처리하도록 설계된 방식이다.</p>
<p>ARM과 AVR은 RISC 계열에 속한다.</p>
<p>주요 특징은 다음과 같다.</p>
<ul>
<li>비교적 단순한 명령어 구조</li>
<li>레지스터 중심의 연산</li>
<li>명령어 처리 규칙이 일정함</li>
<li>Pipeline 적용에 유리함</li>
</ul>
<h3 id="132-cisc">13.2 CISC</h3>
<p>CISC는 하나의 명령어가 비교적 복잡한 작업을 수행할 수 있도록 설계된 구조다.</p>
<p>대표적인 예로 x86 계열 프로세서가 있다.</p>
<p>과거에는 RISC와 CISC를 단순한 명령어와 복잡한 명령어로 구분했지만, 현재의 프로세서는 내부적으로 여러 최적화 기법을 사용하므로 두 구조를 완전히 단순하게 나누기는 어렵다.</p>
<hr />
<h2 id="14-harvard-architecture">14. Harvard Architecture</h2>
<p>Harvard Architecture는 프로그램 명령어와 데이터를 서로 다른 Memory 공간이나 Bus를 통해 처리하는 구조다.</p>
<p>명령어를 가져오는 작업과 데이터를 읽고 쓰는 작업을 분리할 수 있어 효율적인 처리가 가능하다.</p>
<p>반면 Von Neumann Architecture는 명령어와 데이터를 같은 Memory 공간과 Bus를 통해 처리한다.</p>
<p>구조가 비교적 단순하지만 명령어와 데이터가 같은 통로를 사용하므로 병목 현상이 발생할 수 있다.</p>
<p>실제 AVR과 ARM Cortex-M 계열은 명령어와 데이터 경로를 분리하면서도 필요한 경우 상호 접근할 수 있는 수정형 Harvard 구조를 사용한다고 이해하는 것이 적절하다.</p>
<hr />
<h2 id="15-arm이-임베디드-시장에서-널리-사용되는-이유">15. ARM이 임베디드 시장에서 널리 사용되는 이유</h2>
<p>ARM은 CPU를 직접 생산하기보다 Core 설계를 반도체 회사에 제공한다.</p>
<p>반도체 회사는 ARM의 설계를 바탕으로 자신들의 제품에 필요한 Memory와 주변장치를 추가한다.</p>
<p>각 회사가 CPU 구조를 처음부터 직접 설계하는 것보다 개발 비용과 시간을 줄일 수 있다는 장점이 있다.</p>
<p>ARM 기반 제품이 널리 사용되는 이유는 다음과 같다.</p>
<ol>
<li>다양한 반도체 회사에서 ARM 기반 제품을 생산한다.</li>
<li>제품 선택의 폭이 넓다.</li>
<li>비교적 저렴한 제품이 많다.</li>
<li>소비 전력이 낮은 제품군이 많다.</li>
<li>소형 제품을 설계하기에 유리하다.</li>
<li>높은 처리 성능을 제공한다.</li>
<li>개발 도구와 관련 자료가 풍부하다.</li>
<li>Cache와 Pipeline 같은 성능 향상 기술을 지원한다.</li>
</ol>
<h3 id="cache-memory">Cache Memory</h3>
<p>Cache Memory는 CPU와 Main Memory 사이의 속도 차이를 줄이기 위해 자주 사용하는 데이터나 명령어를 임시로 보관하는 빠른 Memory다.</p>
<h3 id="pipeline">Pipeline</h3>
<p>Pipeline은 하나의 명령 처리를 여러 단계로 나누고, 각 단계가 서로 다른 명령을 동시에 처리하도록 구성하는 방식이다.</p>
<p>이를 통해 여러 명령어를 효율적으로 처리할 수 있다.</p>
<hr />
<h2 id="16-stm32-제품명-읽는-방법">16. STM32 제품명 읽는 방법</h2>
<p>이번 강의에서 사용하는 MCU의 이름은 다음과 같다.</p>
<pre><code class="language-text">STM32F103C8T6</code></pre>
<p>각 문자는 제품의 특성을 나타낸다.</p>
<ul>
<li><code>STM32</code>: ARM 기반 32비트 STM32 MCU 제품군</li>
<li><code>F</code>: 범용 및 성능 중심의 STM32F 계열</li>
<li><code>103</code>: STM32F1 제품군의 세부 라인</li>
<li><code>C</code>: Pin 수와 Package 계열</li>
<li><code>8</code>: Flash Memory 용량 코드</li>
<li><code>T</code>: LQFP Package</li>
<li><code>6</code>: 동작 온도 등급</li>
</ul>
<p>STM32F103C8T6는 일반적으로 다음과 같은 특징을 가진다.</p>
<ul>
<li>ARM Cortex-M3 Core</li>
<li>32비트 MCU</li>
<li>48Pin LQFP Package</li>
<li>64KB Flash Memory</li>
<li>SRAM 내장</li>
<li>GPIO 제공</li>
<li>ADC 제공</li>
<li>Timer 제공</li>
<li>UART, SPI, I²C 제공</li>
</ul>
<p>제품명만 보고 모든 사양을 확정해서는 안 된다.</p>
<p>실제 개발에서는 제조사가 제공하는 데이터시트와 Reference Manual을 확인해야 한다.</p>
<p>같은 STM32F103 계열이라도 Pin 수와 Memory 용량, Package에 따라 사용할 수 있는 기능이 달라질 수 있다.</p>
<hr />
<h2 id="17-stm32-프로그램-실행-과정">17. STM32 프로그램 실행 과정</h2>
<p>STM32에서 작성한 프로그램은 일반적으로 MCU 내부 Flash Memory에 저장된다.
<img alt="" src="https://velog.velcdn.com/images/addung/post/6b009337-aacf-4e33-af0b-c9c9bab1f7b6/image.jpg" /></p>
<p>전체 과정은 다음과 같다.</p>
<ol>
<li>STM32CubeIDE에서 C언어 소스 코드 작성</li>
<li>소스 코드 컴파일</li>
<li>Link 과정을 거쳐 실행 파일 생성</li>
<li>ST-LINK를 이용해 MCU의 Flash Memory에 프로그램 기록</li>
<li>MCU 재시작</li>
<li>Flash Memory에 저장된 프로그램 실행</li>
<li>Debug 기능을 이용해 동작 확인
<img alt="" src="https://velog.velcdn.com/images/addung/post/6c519468-5d6a-4b98-adbc-28b186580d90/image.jpg" /></li>
</ol>
<p>ST-LINK는 단순히 프로그램을 저장하는 역할만 하는 것이 아니다.</p>
<p>프로그램 실행을 일시 정지하거나 Breakpoint를 설정하고, 변수와 Register의 값을 확인하는 Debug 기능도 제공한다.</p>
<p>STM32 개발에서는 주로 ST-LINK와 SWD 방식을 이용해 프로그램을 다운로드하고 디버깅한다.</p>
<hr />
<h2 id="18-stm32-보드의-전원-공급">18. STM32 보드의 전원 공급</h2>
<p>STM32 개발 보드가 정상적으로 동작하려면 안정적인 전압과 충분한 전류가 공급되어야 한다.</p>
<p>대표적인 전원 공급 방법은 다음과 같다.</p>
<ul>
<li>ST-LINK를 통한 전원 공급</li>
<li>USB 단자를 통한 전원 공급</li>
<li>전원 Pin을 통한 공급</li>
</ul>
<h3 id="181-st-link를-통한-전원-공급">18.1 ST-LINK를 통한 전원 공급</h3>
<p>일반적인 실습에서는 ST-LINK를 이용해 프로그램을 다운로드하면서 보드에 전원을 함께 공급할 수 있다.</p>
<p>ST-LINK는 PC의 USB에 연결되어 전원을 공급받고, 연결된 STM32 보드에 전원을 전달한다.</p>
<p>다만 ST-LINK의 종류와 연결 방법에 따라 공급할 수 있는 전류가 다를 수 있다.</p>
<p>센서나 모터처럼 비교적 많은 전류가 필요한 장치를 추가로 연결하면 ST-LINK만으로는 전류가 부족할 수 있다.</p>
<p>이 경우에는 별도의 전원을 사용해야 한다.</p>
<h3 id="182-usb를-통한-전원-공급">18.2 USB를 통한 전원 공급</h3>
<p>USB에서는 일반적으로 5V가 공급된다.</p>
<p>개발 보드에 전압 조정 회로가 포함되어 있다면 USB에서 입력된 5V를 MCU의 동작 전압인 3.3V로 변환하여 공급한다.</p>
<p>보드가 USB 전원을 지원하는지는 사용하는 개발 보드의 회로도와 제품 설명을 통해 확인해야 한다.</p>
<h3 id="183-전원-pin을-통한-공급">18.3 전원 Pin을 통한 공급</h3>
<p>개발 보드의 전원 Pin을 통해 직접 전원을 공급할 수도 있다.</p>
<p>이때 Pin에 표시된 전압을 반드시 확인해야 한다.</p>
<ul>
<li><code>3.3V</code> Pin에는 3.3V 공급</li>
<li><code>5V</code> Pin에는 보드가 지원하는 경우 5V 공급</li>
<li><code>GND</code>끼리 연결</li>
</ul>
<p>3.3V Pin에 5V를 직접 연결하면 MCU나 개발 보드가 손상될 수 있다.</p>
<p>외부 전원과 ST-LINK를 동시에 사용할 때도 서로 다른 전원이 충돌하지 않도록 보드의 회로 구조를 확인해야 한다.</p>
<hr />
<h2 id="오늘-발생한-stm32-연결-오류">오늘 발생한 STM32 연결 오류</h2>
<p>오늘은 STM32CubeIDE 설치와 ST-LINK 연결 과정에서 생각보다 많은 시간을 사용했다.
<img alt="" src="https://velog.velcdn.com/images/addung/post/52e170a2-95da-46eb-a6f7-92d73103ad2a/image.jpg" /></p>
<p>처음에는 노트북에 STM32CubeIDE와 관련 프로그램을 설치했지만, 프로젝트 생성과 디버깅 과정에서 ST-LINK가 정상적으로 연결되지 않았다.</p>
<p>이후 데스크톱에 개발 환경을 다시 설치하고 설정한 결과 같은 보드와 ST-LINK를 정상적으로 연결할 수 있었다.</p>
<p>보드 자체의 문제라기보다는 노트북에 설치된 개발 환경과 경로, ST-LINK Driver 또는 STM32CubeIDE 설정이 완전하게 구성되지 않았을 가능성이 높았다.
<img alt="" src="https://velog.velcdn.com/images/addung/post/8ba646d3-770f-4bfd-b35f-01fbeee727a0/image.jpg" /></p>
<p>특히 STM32 개발 환경은 단순히 STM32CubeIDE 하나만 설치한다고 끝나는 것이 아니라 다음 요소들이 서로 정상적으로 연결되어야 한다.</p>
<ul>
<li>STM32CubeIDE</li>
<li>ST-LINK Driver</li>
<li>ST-LINK 장치 인식</li>
<li>프로젝트의 MCU 설정</li>
<li>Debug Configuration</li>
<li>PC와 보드 사이의 SWD 배선</li>
<li>보드 전원 공급</li>
</ul>
<p>오늘 경험을 통해 코드에 오류가 없어도 개발 환경이나 하드웨어 연결 상태 때문에 프로그램을 보드에 올리지 못할 수 있다는 것을 알게 되었다.</p>
<p>또한 이런 과정속에서 알게된 내용은, 한 개의 STM32 보드를 특정 컴퓨터 한 대에서만 사용해야 하는것은 아니라는 사실.</p>
<p>노트북과 데스크톱에 각각 STM32CubeIDE와 ST-LINK Driver가 정상적으로 설치되어 있다면 같은 보드를 여러 컴퓨터에서 번갈아 사용할 수 있다는 내용을 찾아 볼 수 있었다.</p>
<p>프로그램이 저장된 프로젝트 폴더의 경로가 서로 다르더라도 프로젝트 내부 파일이 올바르게 유지된다면 개발에는 문제가 없다. (데스크탑은 c드라이브, 노트북은 d드라이브에 프로젝트 폴더가 생성되어있음)</p>
<p>다만 두 컴퓨터에서 같은 프로젝트를 계속 수정하려면 프로젝트 파일을 직접 복사하거나 GitHub와 같은 버전 관리 도구를 사용하는 것이 편리하다는 사실!</p>
