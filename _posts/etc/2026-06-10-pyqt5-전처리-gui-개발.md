<p>한이음 드림업 프로젝트에서 자전거 이용자 안전을 위한 도로 이상 객체 탐지 시스템을 개발하고 있는중이다.</p>
<p>AI Hub에서 받은 도로 이상 이미지 데이터를 그대로 쓸 수 없었다. 원본 이미지는 1920×1080 크기인데, 라벨은 이미지 1장당 JSON 1개로 붙어 있고 bbox 형식도 <code>[x, y, width, height]</code> 픽셀 좌표라서 YOLOv8, RT-DETR, EfficientDet-d3 같은 모델 학습에 바로 넣기가 어려웠다.</p>
<p>그래서 AI Hub JSON 라벨을 학습 가능한 형식으로 변환하고, 이미지 크기와 bbox 좌표를 함께 보정하는 전처리 프로그램을 직접 만들게 됐다.</p>
<hr />
<p><img alt="" src="https://velog.velcdn.com/images/addung/post/cbd4c961-bb56-413c-8b69-95bc15a49eb7/image.png" /></p>
<h2 id="1-gui로-만들기">1. GUI로 만들기</h2>
<p>처음엔 그냥 Python 스크립트로 돌리려 했는데, 막상 작업하다 보니 불편한 점이 많았다.</p>
<ul>
<li>데이터가 많아서 전체 처리 전에 샘플 테스트가 필요했다</li>
<li>모델마다 입력 이미지 크기가 달랐다 (640, 896)</li>
<li>YOLO txt랑 COCO json 두 형식을 모두 뽑아야 했다</li>
<li>기존 train/val/test 구조를 그대로 쓰는 경우도 있고, 원본 클래스별 폴더를 새로 나눠야 하는 경우도 있었다</li>
<li>crop 이후에 bbox가 실제로 맞는지 눈으로 확인하고 싶었다</li>
<li>처리 중 오류 난 파일을 따로 추적하고 싶었다</li>
</ul>
<p>그냥 스크립트 하나로 처리하기엔 관리할 경우의 수가 너무 많아서, 파이썬 수업때에 배운 PyQt5로 GUI를 만드는 게 낫겠다고 판단하여 실행.</p>
<hr />
<h2 id="2-사용한-데이터-구조">2. 사용한 데이터 구조</h2>
<p>7개 클래스를 사용했다.</p>
<pre><code>0: manhole
1: pothole
2: flood_area
3: box
4: water_container
5: kickboard
6: trash_pile</code></pre><p>문제는 AI Hub JSON 라벨에 클래스명이 <code>12.맨홀</code>, <code>26.포트홀</code>, <code>27.침수구간(웅덩이)</code> 같은 형식으로 들어 있다는 점이었다. 그래서 원본 라벨명과 프로젝트 클래스명을 매핑하는 <code>class_map.json</code>을 따로 만들었다.</p>
<pre><code class="language-json">{
  &quot;12.맨홀&quot;: &quot;manhole&quot;,
  &quot;26.포트홀&quot;: &quot;pothole&quot;,
  &quot;27.침수구간(웅덩이)&quot;: &quot;flood_area&quot;
}</code></pre>

<h2 id="3-주요-기능">3. 주요 기능</h2>
<p><img alt="" src="https://velog.velcdn.com/images/addung/post/0d1524d5-0a7f-435d-a372-20db5b8f6686/image.png" /></p>
<h3 id="입력-구조-선택">입력 구조 선택</h3>
<p>두 가지 방식을 지원하도록 만들었다.</p>
<p><strong>방식 1 - 기존 split 구조 유지</strong></p>
<p>이미 train/val/test로 나뉜 폴더를 그대로 사용하는 방식이다.</p>
<pre><code>04_split
├── train
├── val
└── test</code></pre><p><strong>방식 2 - 클래스별 원본 폴더 자동 분할</strong></p>
<p>클래스별로 정리된 원본 폴더를 입력받아 내부에서 7:2:1로 자동으로 나눈다.</p>
<pre><code>raw_dataset
├── 00_manhole
├── 01_pothole
├── 02_flood_area
├── 03_box
├── 04_water_container
├── 05_kickboard
└── 06_trash_pile</code></pre><p>원본 파일은 이동하거나 수정하지 않고, JSON 파일 목록만 내부적으로 나눠서 출력 폴더에 결과를 생성하도록 설계했다.</p>
<hr />
<h3 id="모델별-이미지-크기-선택">모델별 이미지 크기 선택</h3>
<pre><code>YOLOv8 / RT-DETR: 640×640
EfficientDet-d3: 896×896</code></pre><p>단순 resize가 아니라 bbox 중심을 기준으로 지정 크기만큼 crop하는 방식을 썼다. 객체가 이미지 가장자리에 있으면 crop 영역이 이미지 밖으로 나가기 때문에, 그 경우 안쪽으로 이동시키는 보정 로직도 따로 넣었다.</p>
<hr />
<h3 id="yolo-txt--coco-json-선택-생성">YOLO txt / COCO json 선택 생성</h3>
<p>출력 라벨 형식은 체크박스로 선택할 수 있게 했다.</p>
<pre><code>☑ YOLO txt 생성![](https://velog.velcdn.com/images/addung/post/008ab35c-a87f-4802-8ad8-8421dceb45cc/image.png)

☑ COCO json 생성</code></pre><p>YOLO txt는 아래 형식으로 저장된다.</p>
<pre><code>class_id center_x center_y width height</code></pre><p>COCO json은 아래 구조로 저장된다.</p>
<pre><code class="language-json">{
  &quot;images&quot;: [],
  &quot;annotations&quot;: [],
  &quot;categories&quot;: []
}</code></pre>
<p>YOLOv8, Ultralytics RT-DETR은 YOLO txt + data.yaml 조합으로 학습하고, EfficientDet 계열은 COCO json을 쓰면 된다.</p>
<hr />
<p><img alt="" src="https://velog.velcdn.com/images/addung/post/4bddcd43-4000-4bbd-b617-d692248ec90f/image.png" /></p>
<h3 id="bbox-미리보기">bbox 미리보기</h3>
<p>전처리가 끝나면 YOLO txt 라벨을 다시 읽어서 crop 이미지 위에 bbox를 그려주는 미리보기를 생성한다.</p>
<p>확인할 수 있는 항목은 다음과 같다.</p>
<ul>
<li>bbox가 실제 객체를 제대로 감싸는지</li>
<li>crop 후에도 객체가 이미지 안에 남아 있는지</li>
<li>클래스 ID가 맞는지</li>
<li>좌표 변환이 정상적으로 됐는지</li>
</ul>
<p>미리보기 이미지는 <code>preview_bbox</code> 폴더에 split별로 저장된다.</p>
<hr />
<h3 id="오류-리포트">오류 리포트</h3>
<p>전처리 중 오류가 난 파일은 <code>preprocess_report.txt</code>에 기록된다. 처리 통계랑 오류/경고 목록이 같이 남아서 나중에 어떤 파일이 실패했는지 추적하기 편리하다.</p>
<p>리포트에 포함되는 내용은 아래와 같다.</p>
<ul>
<li>입력/출력 폴더 경로</li>
<li>crop 크기</li>
<li>전체 JSON 수, 성공/실패 수</li>
<li>split별, 클래스별 처리 수</li>
<li>오류 목록 및 경고 목록</li>
</ul>

<h2 id="5-구현하면서-막혔던-부분들">5. 구현하면서 막혔던 부분들</h2>
<h3 id="ai-hub-라벨명-불일치">AI Hub 라벨명 불일치</h3>
<p>JSON 안의 label 값이 통일되어 있지 않았다. <code>26.포트홀</code>이랑 <code>26. 포트홀</code>처럼 공백 하나 차이로 두 가지가 섞여 있었다. <code>class_map.json</code>에 alias를 추가하고, 읽을 때 공백 제거 처리를 함께 적용해서 해결했다.</p>
<hr />
<h3 id="json-인코딩-문제">JSON 인코딩 문제</h3>
<p>일부 JSON 파일이 UTF-8이 아닌 cp949나 euc-kr로 저장돼 있었다. 처음엔 <code>utf-8 codec can't decode</code> 오류가 계속 났는데, 인코딩을 순서대로 시도하는 방식으로 고쳤다.</p>
<pre><code>utf-8 → utf-8-sig → cp949 → euc-kr</code></pre><hr />
<h3 id="이미지-파일명-불일치">이미지 파일명 불일치</h3>
<p>JSON의 <code>images.filename</code> 값이랑 실제 이미지 파일명이 다른 경우가 있었다. 그래서 이미지를 찾을 때 아래 순서로 탐색하도록 구현했다.</p>
<pre><code>1. JSON filename 그대로 탐색
2. JSON 파일명 stem 기준으로 탐색
3. 확장자 png/jpg/jpeg 바꿔서 탐색
4. 유사 prefix 기준으로 탐색</code></pre><hr />
<h2 id="6-결과-폴더-구조">6. 결과 폴더 구조</h2>
<pre><code>output_dataset
├── images
│   ├── train
│   ├── val
│   └── test
│
├── labels
│   ├── train
│   ├── val
│   └── test
│
├── coco
│   └── annotations
│       ├── instances_train.json
│       ├── instances_val.json
│       └── instances_test.json
│
├── preview_bbox
│   ├── train
│   ├── val
│   └── test
│
├── data.yaml
└── preprocess_report.txt</code></pre><p>Object Detection 학습에서는 이미지를 클래스별 폴더로 나눌 필요가 없다. 클래스 정보는 YOLO txt의 class_id, COCO json의 category_id에 이미 들어가 있기 때문이다.</p>

<h2 id="8-느낀점">8. 느낀점</h2>
<p>모델 학습 코드보다 데이터 전처리 구조를 제대로 설계하는 게 훨씬 중요하다는 걸 이번에 직접 느꼈다.</p>
<p>이미지 크기를 바꾸는 순간 bbox 좌표도 같이 변환해야 하고, 라벨 형식도 모델마다 다르다. YOLO랑 COCO를 모두 지원하게 만들어두니까 나중에 모델 바꿀 때 훨씬 편했다.</p>
<p>데이터셋 규모가 커질수록 전체 처리 전에 작은 샘플로 먼저 돌려보고, 오류 파일을 리포트로 남기는 게 얼마나 중요한지도 체감했다. 처음에 그냥 스크립트로 돌렸으면 오류 추적이 훨씬 힘들었을 것 같다.</p>
